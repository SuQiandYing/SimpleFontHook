# Artemis Legacy 适配器

## 职责

本目录负责使用 `.iet` 脚本、文本脚本和 `.rft` 预渲染字体资源的 Artemis 布局。适配器
为脚本提供字体路径、字号、间距和文字映射，并通过版本化虚拟字体资源连接通用字体配置。

## 为什么独立于 Artemis 表布局

该布局在 `.iet` 或文本脚本中描述字体，并可通过 `.rft` 提供预渲染结果。它使用的字段、
资源路由和运行时对象与 `list_windows*.tbl` 布局不同。把两种布局合并会让一个共享后缀
或归档同时触发不相干的处理器，也会把不同缓存结构放进同一刷新逻辑。

独立适配器以 PFS 内脚本资源确认身份，把脚本、预渲染字体和虚拟 SFNT 分别分类，再由
统一文件分派器按实际请求选择处理路径。

## 身份与资源

IET 布局由 PFS 头与索引解析结果确认。解析器校验归档索引的条目数量、路径边界和
20 字节资源元数据，索引内的 `system` 或 `_base` 运行时资源域包含 `.iet` 时建立
IET 布局身份。

PFS 中的 IET 和文本脚本通过归档索引定位并读取；游戏根目录中的同路径文件属于资源
覆盖入口，不参与引擎身份确认。
`.iet`、`.rft` 和字体后缀只在 Artemis 身份成立后参与资源分类。表文件与 IET 文件各自
进入对应处理器；实际请求对应的松散文件可作为资源覆盖来源。

## 文件结构

- `artemis_legacy_paths.cppinc`：布局检测、字体源定位、虚拟路径和资源分类。
- `artemis_legacy_iet_patch.cppinc`：IET/文本脚本中的字体、渲染、间距和文字字段处理。
- `artemis_legacy_file_hooks.cppinc`：松散文件或 PFS 资源的脚本读取，以及字体的只读虚拟
  文件句柄和属性。
- `artemis_legacy_text_substitution.cppinc`：该布局的多字节转 Unicode 文字映射入口。
- `artemis_legacy_notify.cppinc`：配置版本通知、字体准备和热切换状态记录。
- `../common/engine_font_export.cppinc`：共享 GDI 字体导出和 SFNT 数据校验。

## 实现原理

1. PFS 解析器验证索引，并在 `system` 或 `_base` 资源域中查找 IET 契约。
2. 路径模块将松散文件与归档条目统一为脚本、RFT 和字体三类请求。
3. 脚本处理器在有界字段内修改字体路径、字号、注音字号、字距、行距和渲染标记。
4. 文字字段按明确的 ANSI 源代码页解码，再调用通用 Unicode 映射；该路径与字体替换
   配置保持独立开关。
5. 字体导出器生成当前版本 SFNT，文件处理器以只读虚拟句柄发布脚本与字体内容。
6. 配置通知提前准备字体资源，并记录脚本处理、打开和重定向所消费的版本。

## 功能

### 脚本处理

脚本处理覆盖字体文件字段、字体变量、姓名文本上下文、预渲染标记、`kerning`、行距、
`size` 与 `rubysize`。文字映射按配置的 ANSI 源代码页解码，再调用通用 Unicode 映射表。

### 字体资源

虚拟字体默认位于 `_base/font/FontHook.ttf`，文件名包含配置版本后缀。字体内容可以来自
当前用户字体、系统字体、游戏本地字体或 GDI SFNT 数据。TTC 源按字体名称选择字体面，
并应用字符集能力、垂直度量和 `cmap` 别名配置。

### 热切换

配置通知准备当前版本字体，并记录脚本打开、脚本处理和字体重定向版本。新的脚本或字体
读取请求直接获得当前 `ConfigVersion` 对应的内容。

## 设计理由

- 脚本在读取时形成版本化视图，磁盘和 PFS 原始资源保持只读。
- RFT 隐藏与虚拟 SFNT 交付分别受资源分类控制，使实时字体路径只在身份和配置成立时
  生效。
- 文字映射使用线程局部递归保护调用真实转换 API，避免脚本处理再次进入自身钩子。
- 松散覆盖文件只提供资源内容，不参与身份确认；身份仍来自经过解析的 PFS 契约。
- 每类请求记录配置版本，便于判断脚本内容、字体路径与字体字节是否来自同一快照。

## 配置

- `EnableArtemisHook`
- `ArtemisPatchTables`
- `ArtemisRedirectFontFiles`
- `ArtemisFontPath`
- `ArtemisFontSize`
- `ArtemisRubySize`
- 通用字体、字符集、文字映射、字距、行距和垂直度量配置

## 运行约束

- 资源路径必须位于游戏根目录内，并匹配已知脚本或字体扩展名。
- 脚本解析对字段范围、引号、数字和二进制输入执行边界检查。
- 文字映射通过线程局部递归保护调用真实 `MultiByteToWideChar`。
- 文件虚拟化只处理读取和属性查询，文件分派优先级集中维护。
- 每个缓存项和诊断状态都关联明确的配置版本。

## 验证

覆盖 IET 松散文件、PFS 内 IET、字体变量、姓名文本、RFT 路径、TTC 字体、文字映射、功能
开关、连续热切换、损坏脚本和 Artemis 表文件布局。
