# BGI 兼容适配器

## 职责

本目录处理 32 位 GDI 字形栅格化流程中的字体度量、IAT 调用和字形缓存兼容。BGI
身份由 Buriko 模块标记或 BURIKO 归档魔数确认，栅格化导入与缓存布局负责能力确认；
文本代码页由通用编码模块独立管理。

## 通用路径覆盖范围

BGI 的 Win32 栅格流程会经由模块 IAT 调用 GDI，并把字形尺寸与位图写入内部缓存。仅在
系统入口替换字体时，部分调用可能绕过预期的钩子入口；即使字体对象已经替换，源字体与
目标字体的墨迹范围差异也可能破坏引擎为缓存分配的宽高。

适配器因此同时处理三个层面：确认 Buriko 身份与栅格能力、把目标模块导入槽连接到通用
钩子、按源字体测量结果归一化替换字体度量。运行时缓存刷新只作为已经验证布局上的版本
同步动作。

## 支持范围

完整适配面向 Win32 栅格化布局。x64 提供相同调用接口，运行时状态保持未激活。

## 文件结构

- `bgi_compat.cppinc`：命名空间和实现聚合入口。
- `bgi_compat_state.cppinc`：导入、缓存布局、实例版本和度量状态。
- `bgi_import_detection.cppinc`：PE 导入表检查和栅格化流程特征。
- `bgi_cache_detection.cppinc`：在有界代码范围内定位缓存访问布局。
- `bgi_cache_hooks.cppinc`：缓存函数钩子、版本观察和 GDI 导入修补。
- `bgi_font_metrics.cppinc`：字体探测、宽高比例和垂直度量辅助函数。
- `bgi_runtime.cppinc`：安装、度量归一化、文本输出作用域和配置刷新接口。

## 激活流程

1. 检查 `EnableBgiHook`。
2. 检查 `Buriko General Interpreter`、`BURIKO ARC` 模块标记或候选归档头魔数。
3. 读取主模块 PE 并分类字体创建、栅格输出、`SelectObject` 和辅助 GDI 导入。
4. 根据配置定位并挂接缓存布局。
5. 根据配置修补目标模块的 GDI 导入槽。
6. 只有实际安装了缓存钩子或导入修补后才设置活动状态。

`.arc` 后缀和 GDI 导入组合可被其他引擎复用。适配器先确认 BGI 身份，再验证完整
栅格能力，两个阶段同时成立才允许缓存钩子和 IAT 修补。

## 实现原理

1. 身份检测从模块标记或 BURIKO 归档头获得强证据。
2. PE 导入解析确认字体创建、选择与栅格输出入口，形成当前版本的能力集合。
3. 有界代码扫描定位缓存头、计数与哨兵访问模式，并验证目标地址和内存保护。
4. Detours 事务挂接缓存函数，IAT 修补把引擎内部 GDI 调用指向已安装的兼容入口。
5. 度量模块分别测量源字体和候选替换字体，在有限范围选择宽高并缓存计算结果。
6. `ConfigVersion` 变化时，只清理由已验证实例和布局描述的字形缓存。

## 度量归一化

适配器分别测量原字体和替换字体的字形墨迹范围、总宽度和 `TEXTMETRIC`，在有限候选
范围内选择替换字体宽高。结果按源 LOGFONT、目标 LOGFONT 和 `ConfigVersion` 缓存。
内部字体探测使用 `ScopedInternalFontProbe`，避免探测字体再次进入替换钩子。

## 缓存刷新

缓存实例以有限槽记录最近看到的 `ConfigVersion`。当前版本只刷新已验证布局的缓存；
布局或实例校验失败时保持对应内存内容。

## 设计约束依据

- 身份、导入能力和缓存布局分开验证，避免“使用 GDI 的程序”被当作 BGI。
- IAT 修补面向目标模块自身的调用路径，通用系统入口仍由统一 Detours 模型管理。
- 度量归一化使用真实字形墨迹而非固定比例，兼顾不同字体的空白边与基线差异。
- 缓存布局扫描有长度和映像边界，刷新操作只写入已证明含义的字段。
- 内部字体探测通过 `ScopedInternalFontProbe` 旁路替换，测量输入保持源字体与目标字体
  可区分。

## 配置

- `EnableBgiHook`
- `BgiPatchGdiImports`
- `BgiClearGlyphCacheOnSwitch`

## 不变量

- 本适配器不解码 ANSI 文本，不强制 CP932，也不参与文字映射代码页选择。
- PE、函数体和缓存布局扫描必须有严格的映像范围与最大长度限制。
- 未形成完整兼容证据时不得修改 IAT 或缓存。
- 度量探测失败时使用未经归一化的通用替换字体。
- 修补点扩展同时提供非目标程序的负向验证。

## 证据与复刻

1. 对 Win32 主模块执行 `dumpbin /headers` 和 `dumpbin /imports`，记录映像范围、GDI 导入槽
   与 Buriko 模块标记；候选归档另记头魔数和 SHA-256。
2. 先运行身份判断，再运行字体创建、选择、栅格输出导入分类；两个结果分别保存。
3. 记录 IAT 槽在事务前后的目标模块、函数名和地址归属，不把地址值作为跨构建常量。
4. 以固定源字体和目标字体采集墨迹范围、总宽度、`TEXTMETRIC` 与归一化结果。
5. 以有效和无效缓存布局执行配置切换，记录实际写入字段、`ConfigVersion` 和回退原因。

| 场景 | 身份 | 能力 | 预期结果 |
| --- | --- | --- | --- |
| Buriko 证据 + 完整 GDI 栅格导入 | 通过 | 通过 | 安装所配置的 IAT/缓存路径 |
| 只有 GDI 导入 | 不通过 | 不执行 | 不修改 IAT 与缓存 |
| 身份成立但缓存布局缺失 | 通过 | 部分 | IAT/度量可用，缓存内存保持不变 |
| x64 进程 | 可记录身份 | Win32 布局不激活 | 使用通用钩子 |

诊断材料包含 `[DEBUG][BGI]` 日志、导入快照、度量输入输出、缓存布局证据和非目标样本。
通用字段见 [功能证据与复刻流程](../../../../../docs/reproduction.md)。

## 验证

覆盖 Win32 正向检测、非目标程序、IAT 修补开关、缓存布局命中与缺失、度量探测、字体
热切换和配置关闭。
